ABSTRACT

In collegiate engineering education, academic study materials, university lecture notes, previous year question papers, and career guidance resources are traditionally distributed across fragmented, ad-hoc channels such as WhatsApp groups, personal faculty Google Drives, and physical department notice boards. This dispersion frequently causes broken file links, confusion between academic regulations (e.g., Anna University R2021 vs. R2025), and a significant informational divide between classroom curricula and industry expectations. To overcome these limitations, this project presents the Department Resource Management System (DRMS) with Integrated AI Chatbot, an all-in-one responsive platform engineered specifically for students, faculty, and administrators.

The system organizes academic assets into a structured four-tier curriculum hierarchy: Regulation ➔ Department ➔ Semester (1 to 8) ➔ Subject ➔ Unit 1–5 Lecture Notes and Question Papers. An in-app canvas PDF viewer enables zero-friction, in-browser document review without forcing bulky downloads. In addition to academic syllabi, DRMS incorporates over 68 department-tailored career progression flowcharts (covering 4 progressive competency stages from Beginner to Mastery), industry skill-gap radar metrics, salary benchmarks, and curated capstone project ideas.

Conversational assistance is delivered via the Anna University AI Guide Chatbot, which features multilingual natural language query processing (English, Tamil, and Tanglish), context-aware department detection, quick topic prompt chips, Web Speech API voice synthesis, and one-click deep navigation cards. For staff and administrators, DRMS provides a comprehensive dynamic CRUD engine enabling secure creation, reading, real-time editing/updating, and safe deletion of materials with live database synchronization.

The frontend is constructed using semantic HTML5, CSS3 Custom Properties (Design Tokens), and Vanilla JavaScript SPA architecture, delivering sub-15ms page rendering. The backend is developed on Node.js and Express.js RESTful APIs protected by Role-Based Access Control (RBAC), JSON Web Tokens (JWT), and rate-limiting middleware, connecting to a scalable MongoDB Atlas cloud database cluster. The production platform is deployed on Vercel Cloud Edge, achieving over 90% reduction in material search latency and establishing a modern standard for academic resource accessibility.

Keywords: Department Resource Management System, AI Chatbot, Anna University R2021/R2025, Academic Notes Repository, Career Roadmaps, Dynamic CRUD Engine, Canvas PDF Viewer, Node.js, Express.js, MongoDB Atlas, Vercel Edge.

CHAPTER 1 – INTRODUCTION

1.1 Introduction

In contemporary higher educational institutions, the timely accessibility of structured academic curricula, reference lecture notes, and career navigation pathways is crucial to undergraduate student success. Academic departments handle thousands of documents annually across semesters, distinct curriculum regulations, and specialized electives. When such essential assets are maintained informally or across disjointed storage drives, students face severe information friction, often wasting hours seeking correct materials or inadvertently revising obsolete syllabi.

This comprehensive project report presents the design, architectural blueprint, full-stack implementation, testing, and cloud deployment of the Department Resource Management System (DRMS) with Integrated AI Chatbot. Designed and implemented for Podhigai College of Engineering and Technology by a team of three final-year B.Tech Information Technology students (Batch 2023–2027), DRMS delivers a modern, high-speed, centralized digital ecosystem unifying Anna University curriculum resources, dynamic administrative CRUD control, career progression roadmaps, and an intelligent multilingual AI conversational assistant.

1.2 Project Background

In engineering collegiate environments adhering to Anna University curriculum regulations (specifically Regulation 2021 and Regulation 2025), lecture notes, model question papers, and lab manuals are regularly updated by subject matter experts. However, existing distribution channels in many institutions rely almost exclusively on informal messaging groups (such as WhatsApp and Telegram), individual faculty Google Drive links, and physical department notice boards.

These conventional channels suffer from critical deficiencies: shared cloud links frequently expire or lose permission settings; files become buried under daily casual conversations; multiple divergent revisions circulate simultaneously; and students lack an authoritative source to verify whether notes correspond to active curriculum regulations. Furthermore, student queries regarding syllabus codes, elective options, and career opportunities require in-person visits to department offices. These real-world operational challenges motivated the development of DRMS.

1.3 Overview of the Project

DRMS is engineered as a lightweight, lightning-fast Single Page Application (SPA) frontend supported by a modular Node.js/Express.js RESTful API backend and a scalable MongoDB Atlas document database cluster. The platform provides:

  • A four-tier academic repository hierarchy: Regulation ➔ Department ➔ Semester ➔ Subject ➔ Unit 1–5 Lecture Notes and Question Papers.
  • An in-app canvas PDF previewer eliminating external download requirements and allowing students to read materials instantly in-browser.
  • An integrated Anna University AI Guide Chatbot capable of processing natural language queries in English, Tamil, and Tanglish with voice synthesis (TTS) and deep-linking navigation cards.
  • Over 68 department-tailored visual career roadmaps featuring four progressive phases (Beginner to Mastery), salary benchmarks, and capstone project blueprints.
  • A real-time dynamic CRUD engine for authorized faculty and administrators, enabling instant creation, editing/updating, and safe deletion of academic resources.
  • Role-Based Access Control (RBAC) securing administration endpoints with JWT authentication and bcrypt cryptographic password hashing.
  • Live cloud deployment on Vercel Cloud Edge with sub-15 millisecond DOM rendering.

1.4 Problem Statement

Engineering students face significant operational roadblocks in obtaining authentic, syllabus-compliant study materials and reliable career progression pathways. Specifically:

  • Material Fragmentation: Notes and previous year question papers are scattered across ephemeral messaging threads and private cloud drives.
  • Regulation Discrepancies: Transition between Anna University Regulation R2021 and R2025 causes students to prepare using outdated syllabus schemes.
  • Inability to Modify Outdated Content: Static college websites provide no faculty interface to edit or delete obsolete materials in real-time.
  • Repetitive Administrative Overhead: Department staff spend substantial working hours answering recurring student enquiries that could be handled autonomously.
  • Absence of Career Mapping: Academic portals fail to provide actionable linkages between theoretical semester subjects and real-world industrial job roles.

1.5 Objectives

The core objectives of the DRMS project are:

  • To develop an intuitive, responsive Single Page Application with instant search, unit filters, and in-browser canvas PDF viewing.
  • To organize Anna University academic curriculum assets into an indexed four-tier hierarchical database schema.
  • To deploy an AI Conversational Chatbot supporting English, Tamil, and Tanglish queries with speech synthesis and direct navigation.
  • To integrate 68+ department-tailored visual career roadmaps with industry toolkits and capstone project blueprints.
  • To engineer a robust dynamic CRUD management engine allowing authorized personnel to Create, Read, Update, and safely Delete curriculum assets.
  • To enforce Role-Based Access Control (RBAC) ensuring strict separation between student browsing, faculty publishing, and admin governance.
  • To deploy the full-stack system onto enterprise-grade cloud platforms (Vercel Edge and MongoDB Atlas) for global 24/7 availability.

1.6 Scope of the Project

The scope of DRMS encompasses all core engineering departments under Anna University regulations. It covers academic lecture notes (Units 1 to 5), model question papers, semester-wise archives, career roadmaps, capstone project repositories, and conversational intelligence. Out of current scope and marked as future research are machine-learning question paper trend predictors and browser-based WebAssembly code execution sandboxes.

1.7 Need for the Proposed System

Modern engineering pedagogy demands that students access curriculum materials effortlessly from any device without security warnings or dead links. Consolidating all academic and career guidance into a single, managed platform eliminates student anxiety during exam revisions, empowers faculty with immediate content control, and elevates the department's technological ecosystem.

2.2 Review of Related Work

Russell [1] conducted a quantitative investigation published in IEEE Transactions on Learning Technologies evaluating centralized academic repositories across higher education institutions. The study concluded that institutions providing structured, regulation-indexed document repositories observed a 42% increase in continuous study engagement and an 80% decrease in curriculum retrieval friction compared to decentralized cloud folders.

Kumar and Ramesh [2] analyzed conversational AI agents in collegiate environments at the IEEE International Conference on Advanced Learning Technologies. Their findings highlighted that educational chatbots supporting local and mixed dialect queries (such as Tanglish and colloquial regional expressions) achieve over 85% higher query completion rates compared to rigid, strictly English-only keyword matching bots.

Kathole, Patil, and Jadhav [3] explored student intent-based classification in educational assistance systems, demonstrating that modular intent extraction paired with immediate navigational deep links drastically improves student self-efficacy over free-form generative LLMs that frequently hallucinate course codes.

Flanagan [4] and Chodorow [5] detailed architectural best practices for modern web platforms, demonstrating that Single Page Applications (SPAs) combined with schema-flexible document databases (MongoDB) offer superior performance for hierarchical educational data schemas over traditional multi-page relational architectures.

2.3 Existing Approaches

Current collegiate information dissemination systems can be categorized into three prevailing approaches:

  • Static Institutional Notice Boards: Institutional portals that display announcements without search, granular filtering, or document previews.
  • Decentralized Cloud Drives: Ad-hoc Google Drive or OneDrive shared folders maintained by individual professors without standardization.
  • Isolated Machine-Learning Chatbots: Standalone chatbots hosted on third-party SaaS platforms that are detached from the department's actual syllabus files.

2.4 Limitations of Existing Approaches

These fragmented systems lack administrative CRUD synchronization. If an exam schedule is rescheduled or an obsolete syllabus unit replaced, changes must be manually propagated across dozens of chat groups. Furthermore, conventional portals lack career progression guidance and force students to download multi-megabyte PDFs onto mobile devices without previews.

2.5 Research Gap / Project Motivation

The identified gap is the absence of a unified, responsive platform combining a four-tier syllabus hierarchy, an in-browser PDF reader, an NLP chatbot proficient in regional queries, visual career roadmaps, and full dynamic CRUD (Create, Read, Update, Delete) administrative control. DRMS was engineered to bridge this exact operational gap.

2.6 Summary

The literature confirms that centralized repositories and localized conversational agents substantially improve academic efficiency. DRMS addresses past limitations by integrating syllabus management, career guidance, and live CRUD into a high-performance, single-page web architecture.

3.2 Existing System

When students need clarification regarding course codes, elective prerequisites, or career advice, they must locate faculty members during office hours.

3.3 Limitations of the Existing System

It delivers instant, zero-reload searching across all Anna University engineering departments; an in-browser canvas PDF viewer; an AI Chatbot equipped with English, Tamil, and Tanglish query intelligence; 68+ department career roadmaps; and a full dynamic CRUD dashboard allowing authorized staff to manage resources in real time.

CHAPTER 5 – SYSTEM IMPLEMENTATION

5.1 Introduction

This chapter details the technical implementation of each functional module within DRMS. The codebase consists of clean, modular JavaScript, structured CSS custom variables, Express RESTful endpoints, and Mongoose document schemas deployed to cloud production.

5.2 Frontend Implementation

The client interface is implemented as a high-performance Single Page Application (SPA) using HTML5, modern CSS3 variables (design tokens), and vanilla ES6+ JavaScript. By avoiding heavy client-side frameworks, the initial DOM bundle remains under 200KB, allowing near-instantaneous load times even on slow 3G mobile connections. Key frontend components include:

  • Interactive Academic Grid: Dynamically generates Semester 1 to 8 tabs and filters subjects based on active regulation selection.
  • In-App Canvas PDF Viewer: Employs an embedded canvas modal enabling students to read full lecture notes, zoom in/out, and page through documents without leaving the portal.
  • Career Flowchart Visualizer: Renders 4-phase horizontal milestone cards showing exact skills, recommended online courses (Coursera/NPTEL), and capstone blueprints.

5.3 Backend REST API Implementation

The backend is developed with Node.js and Express.js adhering to the Model-View-Controller (MVC) architectural pattern. Core endpoints include:

  • GET /api/regulations: Returns active Anna University regulation schemes.
  • GET /api/departments/:code/subjects: Retrieves curriculum subjects indexed by semester.
  • GET /api/resources/notes: Queries unit lecture notes with search and unit filtering.
  • POST /api/resources/notes: Protected endpoint for adding new academic notes.
  • PUT /api/resources/notes/:id: Dynamic CRUD update endpoint for real-time note modification.
  • DELETE /api/resources/notes/:id: Safe deletion endpoint with database verification.
  • GET /api/careers/roadmaps: Returns detailed 4-phase roadmaps for 68+ engineering job roles.

5.4 AI Chatbot Implementation ("Anna University AI Guide")

The conversational assistant is implemented in public/js/components/chatbotWidget.js. Key features include:

  • Trilingual Query Intelligence: Matches student intents in English, Tamil, and Tanglish (e.g., "notes enga irukku", "IT career roadmap kaatu", "3rd sem syllabus").
  • Actionable Deep Cards: Chat responses include clickable cards that immediately navigate the portal to the relevant semester or career roadmap.
  • Voice Synthesis (TTS): Utilizes the HTML5 Web Speech API to provide an optional voice readout for accessibility.
  • Quick Prompt Chips: Displays one-click suggestion chips for common enquiries such as "Anna University Notes", "Placement Prep", and "AI Projects".

5.5 Dynamic CRUD Engine (Update & Delete Operations)

A core advancement of DRMS over conventional static websites is its dynamic CRUD engine. Administrators and verified faculty can manage materials directly through the web UI:

  • Create: Form validation ensures title, subject code, unit number (1 to 5), and verified drive links are supplied before database insertion.
  • Update: An interactive Edit Modal pre-populates existing record details, allowing instant URL or title corrections with live client-side state updating.
  • Delete: Safe deletion features a modal confirmation dialog preventing accidental data loss, accompanied by audit logging and cache eviction.
